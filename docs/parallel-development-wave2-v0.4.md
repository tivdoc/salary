# Parallel Development Wave 2 V0.4

Wave 2 extends the engineering foundation without authorizing a legal rule, numeric parameter, customer conclusion, source review, source activation, migration, deployment, or external service connection.

## Batch A

- The Wave 1 Git/evidence audit reconciles the registry, source pack, catalog observations, quarantine, ledgers, and change detections. The full-range scanner inventories every changed path, including tests, manifests, lockfiles, scripts, and executable configuration, and pairs static inspection with runtime denial canaries.
- Corpus hardening treats acquisition containers and operative instruments as separate evidence objects. Pension OCR is deterministic derived evidence only; it remains inactive and requires human page/line verification. Amendment relations and commencement/effectivity remain unverified candidates and are never auto-consolidated.
- Controlled import uses a forward-only local journal, fail-closed recovery and a bounded separate-process PDF screener. Persistent owner-import readiness remains empty. Local atomic rename is not a claim of directory-fsync, replicated custody, distributed locking, OS network namespaces, or complete native resource isolation.

All diagnostic readiness commands are separate from strict gates. Diagnostic commands may return exit zero with `not_ready`; strict commands return non-zero until every required gate is satisfied.

## Batch B

- The Minimum Wage review dossier binds source roles, artifact and parser hashes, exact citations, candidate intervals, contradictions and missing gates. Its technical diffs remain `pending_human_review`. Numeric-parameter fixtures are synthetic and the state machine cannot become eligible without two distinct human attestations bound to the exact dossier and source set.
- Canonical Facts now flow through a versioned mapping registry, immutable input snapshot, fail-closed preparation and readiness, the existing legally neutral synthetic runtime, and an internal evaluation record. The record is explicitly not a Finding, eligibility decision, customer report or external-persistence payload.
- Ground Truth tooling defines a versioned two-annotator and human-adjudication workflow, immutable locked revisions, evidence-location validation and deterministic extraction metrics. It uses synthetic fixtures only and denies prohibited paths before I/O.

## Final verification and evidence

Run the complete offline gate with `TIVDOC_LEGAL_NETWORK_DISABLED=1 npm run parallel:wave2:verify`. Expected non-zero exits from strict readiness and environment gates are recorded as successful fail-closed results. Build the final evidence archive with `npm run parallel:wave2:review-package`; the builder requires a clean verified HEAD, two byte-identical clean package trees and ZIPs, fixed archive metadata, manifest verification and consumer-safe extraction.

The required archive is `output/parallel-wave-2/review-package-v0.4.zip`. Its manifest covers every member except the manifest itself, with that recursive-hash exception recorded explicitly.

Engineering completion does not change readiness. Official-source owner handoff, legal review, an isolated persistence environment and human Ground Truth remain required. No source is reviewed or active; no real numeric parameter, Israeli legal rule or Finding is created. Successful Pension OCR remains inactive derived evidence requiring human line-to-page review.
