## למה זה חייב אותך, ולא את המהנדס או את הריצה האוטומטית

זהות סוקר היא ההוכחה שבן אדם בדק. מפתח שנוצר בריצה אוטומטית מבטל את ההוכחה הזו לכל אישור (`attestation`) שייחתם איתו בעתיד — לכן:

- הפקודה `keygen` מסרבת לרוץ תחת `TIVDOC_UNATTENDED=1`.
- הפקודה `register` מסרבת לרוץ גם היא תחת `TIVDOC_UNATTENDED=1`, וגם כשאין טרמינל אינטראקטיבי (למשל מתוך סקריפט).
- החצי הפרטי של המפתח נקרא פעם אחת מהזיכרון, חותם אתגר אחד, ולעולם לא מודפס, לא נרשם ללוג ולא נכתב לשום קובץ דוח.

## הצעדים, בדיוק בסדר הזה

1. **ודא את התנאים:** `TIVDOC_UNATTENDED` לא מוגדר בסביבה שלך; אתה מריץ מטרמינל אינטראקטיבי אמיתי (לא מתוך סקריפט); ה-DEV database פעיל (נבדק בריצה זו: כן).
2. **צור מפתח (על המכונה שלך, פעם אחת):**
   ```
   node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --experimental-strip-types scripts/legal-review-projection/owner-reviewer-identity.mts keygen
   ```
   הפקודה מדפיסה את החצי **הציבורי** של המפתח ואת פקודת ההרשמה המדויקת. החצי הפרטי נכתב לקובץ ההרשאות המקומי (git-ignored) ולא מוצג.
3. **הירשם, עם המזהה שנבחר לך:**
   ```
   node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --experimental-strip-types scripts/legal-review-projection/owner-reviewer-identity.mts register --reviewer-id vladimir-kremen
   ```
   הפקודה מוכיחה בעלות על המפתח (חתימה על אתגר שהשרת הנפיק) ורק אז יוצרת זהות סוקר אמיתית על ה-tenant הייחוסי. הפלט מציג את מזהה הסוקר, התפקיד וה-sha256 של המפתח הציבורי — לא ערך סודי.
