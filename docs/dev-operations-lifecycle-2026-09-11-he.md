# מחזור תפעול DEV שניתן לחזור עליו

הכלי `node scripts/product-workers/dev-lifecycle.mjs` פועל רק מול המסד המבודד, משתמש migrator, תיק QA שבבעלות יעד הבדיקה המאומת ו־Preview תואם ל־worker נקי. הוא אינו כלי להפעלת REAL.

כל פקודה מקבלת `COMMAND PRIVATE_CONFIG_PATH EPOCH_UUID`. קובץ התצורה נשמר מחוץ לריפו, תחת `../release-work`, וכולל `version: managed-dev-lifecycle-v1`, תיק/זהות/כתובת הבעלים, נימוק ההרשאה, `expiresAt` עד ארבע שעות, קובץ אישורי המסד, תבנית סביבת worker פרטית, ledger קיים, קבלת Preview, manifest ו־taskName. סודות אינם מועתקים למסמך הזה.

| פקודה | פעולה |
|---|---|
| `prepare` | הכנת epoch ומפתח מכונה חדשים, שיוך לתיק QA, משימת Windows מתוזמנת מושבתת. retry עם אותו UUID משמר את ההרשאה היחידה. |
| `start` | הפעלת הרשאת epoch שלא בוטלה ובתוקף, supervisor ומתזמן. אינו מחדש סמכות חישוב. |
| `notifications-resume` / `notifications-pause` | הפעלה או השהיה של שליחת הודעות בתוך epoch קיים. ההכנה משאירה אותן מושבתות עד בחירה מפורשת. |
| `status` | מצב המתזמן, קבלת tick אחרונה, תוקף/ביטול מכונה, hash התקציב והערכת החישוב האחרונה. |
| `pause` | הפסקת איסוף/שליחה והרשאת המכונה בלי ביטול סופי של session. אפשר `start` באותו חלון תקף. |
| `stop` | השהיה וביטול session של epoch. הפעלה מחדש של אותו UUID נדחית. |
| `resume` | `prepare` ו־`start` עבור UUID חדש לאחר STOP. חזרה עם אותו UUID אינה יוצרת מפתח או הרשאה נוספים. |
| `authority ... TTL_SECONDS REQUEST_UUID` | פקודה נפרדת: אישור בדיקה סינתטי חתום חדש, המחובר לעובדות השמורות של הקלט הנוכחי. 30–7200 שניות. retry אינו מאריך את האישור. |

לדוגמה, אחרי ההכנה: `node scripts/product-workers/dev-lifecycle.mjs authority <private-config> <epoch-uuid> 120 <request-uuid>`. זו יצירת חתימות **בדיקה**, לא אישור אדם. אי־אפשר להשתמש בה ללא התיק המבודד, העובדות הנוכחיות והצהרות הבדיקה הנדרשות. חתימה שפגה אינה נערכת; נוצרת רשומה חדשה עם מזהה וגרסה חדשים. היסטוריית הדוחות וההערכות נשמרת.

החבילה מאשרת שימוש בקבלות חילוץ שמורות בלבד: `TIVDOC_MANAGED_EXTRACTION_MODE=saved_receipts_only`. אין מפתח OpenAI בסביבת ה־worker שנוצרת, אין יצירת SDK ואין יצירת invocation כשחסרה קבלה. במקרה כזה העבודה נכשלת במפורש עם `provider_receipt_required` ובמספר ניסיונות מוגבל. התקציב המקורי והקבלות אינם מתאפסים. חידוש מכונה אינו הרשאת הוצאה חדשה; הפעלה חיה נוספת מחייבת הרשאת ספק נפרדת.

המשגר והתצורה נוצרים אוטומטית בקבצים פרטיים לפי UUID. השירות הוא Windows Task Scheduler על מחשב DEV; המחשב, המשתמש והרשת צריכים להיות זמינים. `pause`/`stop` אינם הורגים תהליך זר: הם סוגרים את הרשאת העבודה, והילד מסיים או מגיע לגבול הזמן שלו. lease ו־fence של המסד מונעים כתיבה מאוחרת. יש לבדוק `status` וקבלת supervisor לפני שמדווחים שהילד הסתיים. מנעול שנשאר לאחר קריסה נשמר לבדיקה; epoch חדש משתמש בתיקיית supervisor נפרדת, בלי למחוק מנעול או ledger ישנים.

הוכחות ההפעלה, ה־UUID, הגרסה, ה־Preview ומצב השירות בסיום יירשמו במסירת החבילה. ההוראות אינן טענה שההוכחה המשולבת כבר עברה. חסמי REAL נשארים לפי `real-activation-map-2026-09-11-he.md`.
