# Internal saved quote ledger

The v1.1 quote contract and internal PostgreSQL ledger are implemented. They do not open full sales. `issueSavedPriceQuote` requires a server-owned `SavedPricingBasisReader`; no real canonical monetary reader is wired and no HTTP amount/basis argument exists. The current real rules remain inactive. Synthetic evidence in tests is labelled and does not establish an entitlement or a price for a customer.

The caller uses the canonical verified worker transaction for one case. `private.order_quote_context` verifies the actual worker login and installed SID/JTI tenant, locks the case, checks the linked customer identity and contact verification, reads the current saved input, and verifies the initial order against its active entitlement and verified payment row. It uses database time. Unknown credit or monetary basis produces no stored quote. Issuance stores the policy/price/coverage/source/terms snapshot once per request ID; conflicting retries, changed source and expired unpaid use are refused. Earlier quote rows are retained and the runtime has no update/delete privileges.

Credit is reserved separately, when a full order has been constructed. The caller must create that order and call `reserveSavedQuoteCredit` in the **same transaction**, rolling back the whole operation on refusal. The order offer must carry `price_quote_id` and `price_quote_sha256`; amount, months, topics and terms must match the quote exactly. The case lock and unique `credit_order_id` ensure only one order can reserve the same initial credit. Retry produces one reservation and one order event. Paid replay preserves the original reservation after input changes; unpaid use still checks current source and expiry. This is a reservation, not evidence of provider settlement.

There is intentionally no timeout-based credit release. A failed/lost provider response cannot safely make a credit available for another checkout. Verified cancellation/refund reconciliation, atomic creation of the quoted full order, the customer quote/checkout interface and the real monetary-basis reader remain to be implemented. The existing public order creation path still refuses the new full offer without a pricing basis. Historical orders are not rewritten, and an old offer without an exact quote binding cannot consume this credit.

Migration `20260908145315_order_quote_ledger.sql` was applied only to `tivdoc_release_replay_20260907`. It creates two private RLS tables and two private functions with empty search paths, callable only by the worker role. It grants no quote access to web, service, anonymous, authenticated or operations roles. No provider or production configuration changed.

Verification is bounded: 75 local pricing/order/ledger/chain/definer checks, typecheck and lint pass. `P09-quote-ledger-db.json` records nine actual worker/peer/web PostgreSQL assertions, including races, rollback, expiry, foreign scope, runtime immutability, ACLs, source changes and paid replay. The test injects a synthetic basis and a synthetic verified payment, constructs fixture orders separately as the migrator, and does **not** prove atomic customer order creation, canonical monetary correctness, live payment or browser checkout. Each run removes its own synthetic cases/payments/identities and revokes its machine session. The first missing-source failure and initial seven-check receipt are retained. A first cleanup attempt lacked the migrator's tenant setting; its exact two cases were subsequently recovered and removed, and the test now preserves the primary error and ownership manifest.

Supabase CLI 2.117.0 advisors report zero errors and 12 warnings on older public objects: 11 multiple-permissive-policy findings and the existing public `pgcrypto` extension. No quote object is flagged; actual quote ACL checks remain the direct authorization evidence. See `P09-quote-advisors.json`. This checkpoint is not a completed P09 or release candidate.
