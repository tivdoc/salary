# Internal saved quote ledger

The v1.1 quote contract and internal PostgreSQL ledger are implemented. They do not open full sales. `issueSavedPriceQuote` requires a server-owned `SavedPricingBasisReader`; no real canonical monetary reader is wired and no HTTP amount/basis argument exists. The current real rules remain inactive. Synthetic evidence in tests is labelled and does not establish an entitlement or a price for a customer.

The caller uses the canonical verified worker transaction for one case. `private.order_quote_context` verifies the actual worker login and installed SID/JTI tenant, locks the case, checks the linked customer identity and contact verification, reads the current saved input, and verifies the initial order against its active entitlement and verified payment row. It uses database time. Unknown credit or monetary basis produces no stored quote. Issuance stores the policy/price/coverage/source/terms snapshot once per request ID; conflicting retries, changed source and expired unpaid use are refused. Earlier quote rows are retained and the runtime has no update/delete privileges.

The supported internal acceptance entry is `acceptSavedPriceQuote`: it loads the exact saved case/identity quote and calls `private.order_quote_accept`, creating the full order and reserving its credit in one SQL operation. Any refusal rolls back both. The lower-level `reserveSavedQuoteCredit` remains for existing exactly bound orders. The order offer must carry `price_quote_id` and `price_quote_sha256`; amount, months, topics and terms must match the quote exactly. The case lock and unique `credit_order_id` ensure only one order can reserve the same initial credit. Retry produces one reservation and one order event. Paid replay preserves the original reservation after input changes; unpaid use still checks current source and expiry. This is a reservation, not evidence of provider settlement.

There is intentionally no timeout-based credit release. A failed/lost provider response cannot safely make a credit available for another checkout. Cancellation before any provider attempt is implemented below; provider cancellation/refund reconciliation, the customer quote/checkout interface and the real monetary-basis reader remain to be implemented. The existing public order creation path still refuses the new full offer without a pricing basis. Historical orders are not rewritten, and an old offer without an exact quote binding cannot consume this credit.

It creates two private RLS tables and two private functions with empty search paths, callable only by the worker role. It grants no quote access to web, service, anonymous, authenticated or operations roles. No provider or production configuration changed.
