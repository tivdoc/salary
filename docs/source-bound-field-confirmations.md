# Source-bound document readings — P05/P06

The saved worker can ask a customer to confirm a specific uncertain field. It derives the question from the stored extraction, never from an HTTP amount. The immutable target includes the case, product document ID, immutable version and byte hash, purchased month, extraction policy/result hash, candidate ID, normalized value, original confidence and page/locator. The customer can confirm that reading, say that the value differs, or say that it is unreadable. The latter two are not zero and do not supply a replacement amount.

`private.document_field_request_open` requires the actual verified worker principal/session, the current locked input revision and an active paid entitlement for the target month. SQL independently compares the target candidate with its saved checkpoint and current document metadata. A deferred FK commits the target and question together. Concurrent opens and retries return the same request, including its existing answer/expiry. The request month is set from this target, so a February question does not inherit an initial January case month. General historical requests retain their existing behavior.

The original answer uses an identity-checked RPC; corrections use the existing versioned identity-checked answer ledger. The input journal captures the immutable target and actual answer actor/revision. No historical actor is backfilled. The snapshot adapter accepts only a recognized affirmative answer and rechecks its current bytes, version, month, policy, candidate and extraction. Changed source or a negative correction supplies no confirmation to the next snapshot. A provider checkpoint carrying customer confirmations is rejected.

Confirmed readings are attached as metadata to the derived extraction snapshot; the immutable machine checkpoint and its score remain unchanged. The existing canonical resolver independently checks document, case, candidate and normalized extraction hashes. Its `verified` flag means that the identified customer confirmed this reading. For a fully confirmed field whose only remaining issues concern reading confidence/ambiguity, the canonical confidence becomes the confirmed-source grade of 1. This is not a measured probability or an increase in the model's saved confidence. Other fields remain machine readings. Arithmetic discrepancies, impossible values, duplicates, contradictory sources and legal readiness retain their gates. No customer action becomes professional review or a legal attestation.

The analysis code is versioned as `case-analysis@0.6.5`; historical 0.6.0–0.6.4 results remain readable. New source/month work uses the new versioned key; old completed jobs/reports are not rewritten or automatically reactivated. An answer correction changes the input journal and the derived extraction hash.

The thread presents the exact field/month/value and links to a protected request-source endpoint. That endpoint resolves the session's case and actor, checks the stored request/document binding in SQL, then downloads and verifies size and SHA before returning bytes. After replacement it cannot substitute the new file for the old question. An attempt to answer a stale target returns a recoverable conflict. An identity-bound current-source read presents superseded unanswered questions as history and removes them from open counts. Old answered readings remain visible with a historical-source explanation, without a correction form against the new document. A missing or malformed state receipt fails closed. These questions are nonblocking.
