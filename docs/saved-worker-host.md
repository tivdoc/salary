# Saved worker host boundary

`src/server/product/processing/saved-worker-host.ts` binds an externally provisioned machine identity to the existing canonical PostgreSQL root. It returns the `SavedWorkerTransactions` callback consumed by `runSavedDraftOnce`. Every callback gets its own canonical transaction, actual session installation, rotation/actor/tenant verification, worker-principal check, build pin and local statement/lock/idle timeouts. Application holds survive rollback; failed commits remain infrastructure failures and cannot become success.

The host snapshots its case and identity. It has no customer HTTP route, session-minting privilege, publication operation or global case enumerator. Use only the supplied `context.client` inside an operation: a query through another connection is outside that transaction and session. The caller owns closing the connection factory after all work and heartbeat activity have drained.

This root remains limited to disposable development targets. The canonical driver and root now share recognition of dated `tivdoc_release_replay_YYYYMMDD` databases as well as historical `tivdoc_v09_*` names. Remote targets still require the exact host, port and database declaration. `postgres`, production names, undeclared hosts and appended replay-name suffixes are refused. A deployment-ready production target policy and worker entrypoint are not supplied by this change.

Use `NodePostgresConnectionFactory` with the real worker connection string, an exact DEV target and a TLS-verifying pool. The isolated proof uses the existing pinned Supabase root CA. Never disable certificate verification or put connection strings/SID/JTI in logs, source control, browser state or evidence. Machine sessions must already exist with the correct tenant, subject and rotation. Revocation is enforced on the next transaction, including a heartbeat or replay.

Failed BEGIN, COMMIT or ROLLBACK marks the pooled connection for destruction on release. This follows node-postgres's documented [`release(true)` behavior](https://node-postgres.com/apis/pool#releasing-clients); a connection with uncertain transaction state must not serve another session. Three isolated regression tests first failed because release returned those connections to the pool, then passed after the change.

The opt-in proof is `src/server/product/processing/saved-extraction-worker.postgres.test.ts` with `TIVDOC_SAVED_EXTRACTION_DB_PROOF=1`, `TIVDOC_SAVED_HOST_DB_PROOF=1`, the private DEV env-file path and private Storage credential-file path. This mode includes the existing saved-job/Storage scenarios and routes the independently provisioned second case through the actual pooled canonical host. Provider transport is deterministic and injected; it is not an OpenAI or accuracy test. Product case/document rows are removed before their exact owned Storage paths; synthetic canonical audit/report history remains explicitly retained.

The first host proof exposed a cleanup bug: revocation worked, and subsequent cleanup incorrectly attempted to use the revoked session. Its two cases, one request identity and two hash-verified Storage files were recovered and removed using the fixture owner's existing authority. The failure and bounded recovery are preserved in `release-evidence/P05-worker-host-cleanup-first-failed.json`. Cleanup now cancels only owned case/tenant jobs through the fixture owner, never reinstates revoked sessions, and records evidence before and after cleanup. The final live result belongs in `release-evidence/P05-saved-worker-host-db.json` and must be read independently of unit-test results.

## Executable DEV package

The executable command is `scripts/product-workers/saved-draft.mts`; `npm run worker:saved:build` uses pinned esbuild 0.28.2 to produce `output/release-completion/saved-worker/worker.cjs` and its manifest. `npm run worker:saved:run` runs that Node program. It uses the repository's lockfile-installed production dependencies; this is not a dependency-free executable. The build copies the pinned Hebrew font and license and records source, lockfile, font and bundle hashes. A dirty build can prove compilation/disabled behavior, but refuses enabled work. Commit the reviewed source and build from the clean tree before a DEV invocation.

The build uses esbuild's [Node platform and external packages](https://esbuild.github.io/api/#packages). Its server-only marker plugin applies only to this Node bundle; no browser/client import rule is changed. Both source entrypoints and the bundle retain the repository's production/Preview refusal. Application Preview Git deployment does not run this worker.

Configuration is supplied only to the host process. `TIVDOC_SAVED_DRAFT_WORKER_ENABLED=true` is required. `TIVDOC_SAVED_WORKER_CASE_ID` identifies exactly one provisioned case; `TIVDOC_SAVED_WORKER_IDENTITY` is private JSON with its session/token, tenant, actor, null reviewer organization and actual rotation counter. `TIVDOC_SAVED_WORKER_DEV_TARGET` declares host/port/database/project_ref. `TIVDOC_WORKER_POSTGRES_URL` must use that project's actual `tivdoc_worker_runtime` login; TLS certificate verification is enabled with the existing pinned Supabase CA. None of these values belong in command arguments or Git.

`TIVDOC_SAVED_WORKER_REPLAY_ONLY=true` permits only a completed manifest replay. It needs no Storage/provider credentials, throws inside the admission transaction for unfinished work (rolling back any provisional dispatch/claim), and exposes only the saved manifest hash. It cannot act as a second processing path.

Full processing additionally requires `TIVDOC_SAVED_EXTRACTION_PROVIDER_ENABLED=true`, authorized `OPENAI_API_KEY`, `NEXT_PUBLIC_SUPABASE_URL` matching the declared DEV project and private `SUPABASE_SERVICE_ROLE_KEY`. The current model is pinned to the existing extraction policy/default; changing `OPENAI_EXTRACTION_MODEL` to another model is refused until policy/checkpoint versioning is updated. Model API availability and accuracy are not established by an injected-provider test. A run processes one case/job, has a ten-minute stop signal, and drains an in-flight provider result under the provider's own timeout. SIGINT/SIGTERM request graceful interruption. A scheduler must allow that drain; abrupt termination relies on the existing fenced lease and unknown-provider-outcome hold.

Exactly one structured state/reason/manifest-hash summary reaches stdout, including failure. Stderr retains the canonical driver's bounded classification diagnostics, without raw messages, parameters or credentials. Retry/hold/cancel states use a nonzero exit status; busy/idle/disabled are distinct from success. No periodic scheduler, machine-session minting, production activation, customer publication or provider-enabled deployment is created by building this package.

The extended isolated proof uses `TIVDOC_SAVED_BUNDLE_DB_PROOF=1` after a clean bundle build. It checks unfinished replay rollback, then two fresh Node processes reading the completed second-case manifest without provider/Storage credentials, followed by revocation refusal. Its result is separate from the host's 30-check receipt and remains pending until `release-evidence/P05-saved-worker-bundle-db.json` records a successful cleaned run.

Still required: managed session lifecycle, scheduled invocations and unknown-provider-outcome reconciliation; live provider credentials/calibration; reviewed monetary/evidence binding and customer projection/publication. This host is not a deployed daemon, a production activation or completion of P05/P00–P13.
